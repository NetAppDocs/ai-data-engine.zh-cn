= AI Data Engine 架构
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
AI Data Engine（AIDE）在您提供的基础架构上运行。Metadata Engine 扫描您的存储并构建可搜索的目录。NetApp Console 通过 Console 代理管理您的部署。模型上下文协议（MCP）服务器选项允许 AI 客户端在您设置的边界内搜索目录。



[[components]]
== 组件

NetApp Console 中的 AI Data Engine 仪表板、调查和策略均基于元数据目录运行。以下组件构建目录，将其连接到 NetApp Console，并为 AI 客户端提供受管访问。



[[metadata-engine]]
=== Metadata Engine

Metadata Engine 是 AI Data Engine 的核心功能。它扫描您连接的数据源，提取元数据，并将其存储在可搜索的目录中。它不会读取或对文件内容进行分类。Metadata Engine 在每个扫描周期更新目录，检测存储系统中的添加、更改和删除。



[[netapp-console-agent]]
=== NetApp Console 代理

AI Data Engine 需要在您的环境中部署 NetApp Console 代理。Console 代理是一个通用的 NetApp 平台组件，用于维护您的环境与 NetApp Console 之间的连接。它负责处理 NetApp Console 与您的 AI Data Engine 部署之间的身份验证和通信。扫描和编目服务在您的 AI Data Engine 部署中运行，而不是在 Console 代理上运行。


NOTE: 控制台代理并非特定于 AI Data Engine。如果您已经为其他 NetApp 服务部署了控制台代理，则可以使用相同的代理。有关控制台代理部署说明，请参阅 link:https://docs.netapp.com/us-en/console-setup-admin/concept-agents.html["NetApp Console 代理文档"]。



[[governed-access-gateway]]
=== 受管访问网关

受管访问网关是 AI Data Engine 的 MCP 服务器。它允许 AI 客户端搜索元数据目录。网关在您的 AI Data Engine 部署中运行，AI 客户端通过 HTTPS 从您的企业网络或通过 VPN 连接到它。控制台代理不中继 MCP 流量。

Microsoft Entra ID 对用户进行身份验证，并且网关将每个 AI 客户端限制为用户有权搜索的集合。网关仅支持元数据搜索和标记，只有高级用户才能标记文件。它不会检索文件内容。

link:../mcp/learn-about-mcp.html["详细了解受管 AI 访问"]。



[[deployment-types]]
== 部署类型

AI Data Engine 支持两种部署类型。两者都在 Kubernetes 上运行 AI Data Engine 服务。

AIDE 单节点部署:: 在您提供的单个 Linux 虚拟机上运行。安装程序会自动配置 k3s 和支持组件。单节点部署不提供高可用性或水平扩展。
AIDE 多节点部署:: 在您提供的 Kubernetes 集群上运行，适用于需要高可用性的大型环境。


有关受支持的平台、规模估算和基础架构要求，请参阅 link:../deploy/aide-requirements.html["AIDE 要求"]。

对于仅通过出站代理访问 Internet 的环境，每种部署类型也有单独的过程。请参阅link:../deploy/configure-proxy.html["了解 AI Data Engine 的代理"]。

link:../deploy/deployment-overview.html["详细了解部署选项"]。



[[data-flow]]
== 数据流

AI Data Engine 使用两条独立的路径：一条路径用于构建目录并将其提供给 NetApp Console，另一条路径用于服务 AI 客户端。



[[metadata-scanning-and-netapp-console-access]]
=== 元数据扫描和 NetApp Console 访问

. 您将 AI Data Engine 部署在您管理的基础设施上，并将其连接到 NetApp Console 代理。
. 您可以在 *Data sources* 中连接希望 AI Data Engine 编目的数据源。有关详细信息，请参阅link:../data-sources/connect-data-source.html["连接数据源"]。
. Metadata Engine 扫描数据源以提取元数据并在目录中对其进行索引。
. 在 NetApp Console 中，仪表板会从目录中显示存储洞察，而 Investigation 可让您使用元数据过滤器直接查询目录。
. 您可以将搜索条件保存为策略并重新运行它们以识别匹配的文件，还可以对“调查”中的文件执行操作。



NOTE: 目录反映了扫描期间收集的元数据。重新扫描受影响的文件和目录并对结果进行索引后，对源文件的更改将出现在目录中。



[[governed-ai-access]]
=== 受管理的 AI 访问

. 您配置 Microsoft Entra ID，为 AI 访问启用集合，并选择哪些用户可以搜索每个集合。
. 用户将 AI 客户端连接到受管访问网关的 HTTPS 端点，并使用 Microsoft Entra ID 登录。
. 网关会验证用户的访问权限，并将授权请求传递给 Metadata Engine。
. AI 客户端搜索用户可以访问并执行操作的集合中的元数据。
