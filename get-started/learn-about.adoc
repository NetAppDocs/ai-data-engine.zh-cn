= 了解 AI Data Engine
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
AI Data Engine（AIDE）是一种元数据智能服务，可让您查看存储在存储系统中的结构化和非结构化数据。AI Data Engine 扫描您的存储系统并对文件系统元数据进行编目，以便您可以识别存储优化机会、调查数据并执行治理策略。



[[what-ai-data-engine-does]]
== AI Data Engine 的作用

AI Data Engine 扫描您连接的数据源，并构建可在每个扫描周期刷新的可搜索元数据目录。在目录中，您可以：

* *了解您的存储空间。*查看您拥有多少数据、谁拥有这些数据以及它们所在的位置。
* *回收容量。*查找冷数据、陈旧数据和重复数据，并查看哪些数据所有者持有最多的数据，以便您知道要联系谁来进行清理。
* *查找访问风险。*识别具有开放权限的目录，以便为其排定优先级以供审核。
* *调查和整理。*使用元数据筛选器查找您关心的数据，对其进行标记，并将您的标准保存为可随时监控的策略。
* *对数据采取行动。*标记、存档、复制或删除已查看的文件。
* *为人工智能准备数据。*让您授权的 AI 客户端搜索您的元数据并对数据采取行动。




[[storage-optimization-and-data-lifecycle-management]]
== 存储优化和数据生命周期管理

使用元数据来识别需要检查的数据，例如满足组织冷阈值和陈旧阈值的文件以及重复文件。在决定是否保留、标记、归档、复制或删除数据之前，请先调查结果。

存储优化洞察指向机遇。您可能回收的容量取决于您选择采取的操作。



[[governed-ai-access]]
== 受管理的 AI 访问

受管 AI 访问权限允许 AI 客户端在您设置的边界内通过模型上下文协议（MCP）搜索您的元数据。您可以通过创建集合来选择要提供的数据。集合是您向 AI 客户端提供的一组扫描数据。您可以通过定义 Microsoft Entra ID 作用域来控制用户可以搜索哪些集合。

AI 客户端仅使用元数据。它们无法检索文件内容。

link:../mcp/learn-about-mcp.html["详细了解受管 AI 访问"]。



[[who-uses-ai-data-engine]]
== 谁使用AI Data Engine

以下示例展示了不同的人如何使用 AI Data Engine：

* *存储管理员*，他们需要查看满足其组织冷阈值和过时阈值的文件，识别重复文件，并评估存储优化机会。
* *IT 运营团队*，需要集中查看其存储环境中存在的结构化和非结构化数据。
* 使用 AI 客户端搜索授权集合中的元数据并标记他们想要使用的数据的*数据或 AI 团队成员*。
* 正在推出 AI 工具并需要选择 AI 客户端可以搜索哪些集合以及谁可以使用它们的 *IT 主管*。




[[where-ai-data-engine-runs]]
== AI Data Engine 的运行位置

您可以通过 NetApp Console 访问 AI Data Engine，位于 *AI data hub > AI Data Engine* 下。扫描和编录服务在您提供的基础架构上运行，无论是在您的云帐户中还是在您的本地环境中。请选择 Linux VM 上的 AIDE 单节点部署，或者如果您的环境需要大规模的高可用性，请选择 Kubernetes 集群上的 AIDE 多节点部署。

link:../deploy/deployment-overview.html["详细了解部署选项"]。

AI Data Engine 扫描您连接的受支持数据源。有关详细信息，请参阅 link:../data-sources/connect-data-source.html["连接数据源"]。
