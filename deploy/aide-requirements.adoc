= AI Data Engine 要求
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
在部署 AI Data Engine（AIDE）之前，请查看您的环境对网络、Kubernetes、规模和操作系统的要求。对于单节点部署，您只需提供一个 Linux 虚拟机，AI Data Engine 会自动配置其他所有内容。对于多节点部署，请自带 Kubernetes 集群。



[[networking-requirements]]
== 网络要求

必须打开以下网络连接：

[cols="2,1,1,1,2"]
|===
| 连接 | 端口 | 协议 | 方向 | 目的 


| Console agent 到 NetApp Console | 443 | TCP | 出站 | HTTPS：与 NetApp Console 的连接 


| 控制台代理到 ONTAP | 443 | TCP | 出站 | HTTPS：ONTAP 集群发现 


| 控制台代理到 AI Data Engine | 80, 443, 8080, 9000 | TCP | 双向 | Console 代理与 AI Data Engine 之间的通信 


| AI 客户端到 MCP 服务器 | 443 | TCP | 入站 | HTTPS：AI 客户端从您的企业网络或 VPN 访问 AIDE 集群主机名。AI 客户端连接到端口 443 上的主机名。它们不连接到内部服务端口。 


| AI Data Engine 到 ONTAP （NFS） | 111, 2049 | TCP/UDP | 到存储 | NFS 数据源访问 


| AI Data Engine 到 ONTAP （SMB） | 139, 445 | TCP/UDP | 到存储 | SMB 数据源访问 


| 集群节点到 NFS 服务器（多节点配置卷） | 2049 | TCP | 出站 | 对包含 AI Data Engine 配置的导出的 NFS 访问。仅适用于多节点部署。如果使用 Kerberos，管理主机也会装载此导出。 


| AI Data Engine 至 Active Directory | 389、636、3268、3269 | TCP（UDP 也适用于 389） | 出站 | LDAP（389）、LDAPS（636）和全局编录（3268、3269）用于用户身份验证、SMB/CIFS 扫描，以及将 NFS 用户和组 ID 映射到 Active Directory 名称。端口 389 同时使用 TCP 和 UDP；所有其他端口仅使用 TCP。 


| AI Data Engine 到 Kerberos KDC（Active Directory 域控制器） | 88 | TCP/UDP | 出站 | SMB/CIFS 数据源的 Kerberos 身份验证。仅当您使用 Kerberos 时才需要。请参阅 <<kerberos-ad-requirements,Kerberos 和 Active Directory 要求>>。 


| AI Data Engine 到 DNS 服务器 | 53 | TCP/UDP | 出站 | 使用 Kerberos 时文件服务器和 KDC 的名称解析 


| AI Data Engine 到 NetApp 服务、容器注册表和 CDN | 443 | TCP | 出站 | HTTPS：从 CDN 下载安装程序脚本，从 ECR 拉取容器映像和 Helm 图表，从 S3 下载组件目录 
|===

[[vm-sizing]]
[[single-node-vm-sizes]]
=== VM 规模估算

这些大小是建议的基线配置，针对三到四天的初始扫描窗口进行了优化，而不是硬性限制。有关这些数字的驱动因素以及如何超越这些数字，请参阅 <<flexible-sizing-single-node,弹性规格调整准则>>。

[cols="1,1,1,1,1,1,1,1"]
|===
| 大小 | vCPU | RAM | 磁盘 | Storage IOPS | 存储吞吐量 | 网络 | 近似文件 


| 小型 | 16 | 64 GB | 500 GB | 8,000 | 1,000 MB/s | 1 GbE | 2亿 


| 中 | 32 | 128 GB | 2 TB | 12,000 | 1,500 MB/s | 1 GbE | 10 亿 


| 大型 | 96 | 192 GB | 6 TB | 16,000 | 2,000 MB/s | 10 GbE | 30亿 
|===

NOTE: 建议对所有部署规模使用 NVMe SSD 或其他固态存储。此表中的磁盘值仅反映 AIDE 数据卷存储。如果操作系统、k3s 运行时和 AIDE 数据均共享单个磁盘，请在所选规模的磁盘值基础上额外增加约 65 GB。例如，单个磁盘上的小型部署总共需要约 565 GB。


NOTE: 对单节点部署上的 AIDE 数据卷使用块存储，而不是 NFS。NFS 支持的存储可能会导致性能不佳。



[[flexible-sizing-guidelines]]
[[flexible-sizing-single-node]]
=== 弹性规格调整准则

<<single-node-vm-sizes,小型、中型和大型配置>> 是三到四天初始扫描窗口的推荐基线，而不是软件强制执行的硬性限制。

规模估算建议的依据::
+
--
* *文件和目录总数*：要编目的对象总数是计算和存储需求的主要驱动因素。对象数量越多，所需的内存、CPU 和存储也越多。
* *目录结构*：资源使用因目录嵌套深度以及文件在共享和卷之间的分布方式而异。深度嵌套或高度碎片化的结构所需资源可能多于扁平层次结构中相同文件数量所需的资源。
* *所需扫描吞吐量*：初始目录完成速度与 CPU 和内存分配直接相关。配置低于建议规格会降低吞吐量并延长初始扫描时间窗口。
* *存储性能*：强烈建议使用高性能存储。元数据索引和事件处理需要与部署规模成比例的持续 IOPS 和吞吐量。


--
如果您配置的规模过小或超出了部署规模，会发生什么::
+
--
每个配置都针对特定的文件数量和扫描速率进行了调整。如果您的环境超出了配置支持的范围，则可能会出现以下情况：

* *扩展的初始目录持续时间*：减少计算量会降低每天扫描的对象数。例如，以 30 亿个对象为目标但以较小规模进行配置的部署，可能需要远超三到四天目标时间的时间。
* *降低持续摄取吞吐量*：在持续负载下，新文件事件和增量扫描更新的处理速度会变慢。
* *停滞的扫描*：AI Data Engine 组件根据您部署的大小进行配置。当环境显著超过该大小时，扫描可能会停滞，而不仅仅是减慢速度。要检查不正常的工作负载和资源限制，请参阅 link:../administer/monitor-deployment-health.html["监控部署运行状况并调查问题"]。
* *存储容量风险*：相对于对象总数而言，存储规模过小可能会将元数据索引推向容量阈值。请联系 NetApp 支持人员以规划存储扩展。


--
扩展超出建议的大小::
+
--
AI Data Engine 组件根据您部署的大小进行配置，因此向主机虚拟机添加 vCPU、内存或存储不会自动增加容量。如果所需的文件数或性能超出部署的大小，请联系 NetApp 支持部门以重新调整大小。


NOTE: 单节点部署不支持高可用性或水平横向扩展。如果您的环境始终超过 30 亿个文件，或者您需要高可用性和容错，请改为部署 link:deploy-aide-multi-node.html["AIDE 多节点部署"]。

--

[[flexible-sizing-guidelines]]
[[flexible-sizing-multi-node]]
=== 弹性规格调整准则

<<multi-node-sizes,小型、中型和大型配置>> 是推荐的三到四天初始扫描窗口的基线集群配置，而不是由软件强制执行的硬容量上限。超过 60 亿个文件的环境需要与 NetApp 进行自定义规模估算。

规模估算建议的依据::
+
--
* *文件和目录总数*：对象总数是存储和计算要求的主要驱动因素。较大的环境需要额外的集群节点来分配处理负载并保持性能。
* *高可用性复制*：多节点部署默认启用跨节点的数据复制，以实现容错。与同等的单节点部署相比，复制增加了总存储和内存需求。
* *节点计数和工作负载分布*：处理吞吐量和总目录容量随集群中的节点数量扩展。额外节点可在整个集群中分布索引工作负载和存储容量。
* *所需的扫描吞吐量*：集群范围内的 CPU 和内存分配决定了每日扫描速率以及初始目录完成的速度。
* *每节点存储性能*：强烈建议在每个节点上使用高性能存储，总集群容量随节点数量成比例扩展。


--
如果您配置的规模过小或超出了部署规模，会发生什么::
+
--
每个配置都针对特定的文件数量和扫描速率进行了调整。如果您的环境超出了配置支持的范围，则可能会出现以下情况：

* *扩展的初始目录持续时间*：节点数量减少或每节点资源降低会降低吞吐量，从而按比例延长初始目录窗口。
* *峰值负载下的处理延迟增加*：集群内存不足可能会导致高容量摄取期间的处理延迟增加。
* *停滞的扫描*：AI Data Engine 组件根据您部署的大小进行配置。当环境显著超过该大小时，扫描可能会停滞，而不仅仅是减慢速度。要检查不正常的工作负载和资源限制，请参阅 link:../administer/monitor-deployment-health.html["监控部署运行状况并调查问题"]。
* *存储容量风险*：目标对象计数的集群存储不足可能会将元数据索引推向容量阈值。请联系 NetApp 支持部门以规划存储扩展。


--
扩展超出建议的大小::
+
--

[[kerberos-and-active-directory-requirements]]
[[kerberos-ad-requirements]]
== Kerberos 和 Active Directory 要求

在使用 Kerberos 身份验证扫描 SMB/CIFS 共享或将 NFS 用户和组 ID 映射到 Active Directory 名称之前，请先查看这些要求。时间同步、DNS 和主机包要求仅适用于 Kerberos。AIDE 是 Kerberos 客户端：它向您现有的 Kerberos 密钥分发中心（KDC）进行身份验证，并且不充当 Kerberos 服务器。



[[time-synchronization]]
=== 时间同步

当 AIDE 节点和 KDC 上的时钟相差超过允许的时钟偏差时，Kerberos 身份验证将失败。默认情况下，Active Directory 允许的最大差异为五分钟。

请验证以下信息：

* 网络时间协议（NTP）在所有 AIDE 节点上均处于活动状态。
* AIDE 节点使用与域控制器同步的时间源。




[[dns]]
=== DNS

满足以下 DNS 要求：

* 每个 AIDE 节点都可以通过完全限定的域名（FQDN）解析文件服务器和 KDC。
* 如果将节点配置为使用 Active Directory DNS 服务器，则该服务器还必须解析外部名称。否则，AIDE 无法访问 <<outbound-internet-access,出站互联网接入>> 中列出的端点。
* 如果更改多节点部署上的 DNS 设置，请将 Active Directory DNS 服务器配置为每个节点上的唯一名称服务器。集群中的名称解析会随机选择一个列出的名称服务器，因此无法解析 Active Directory 名称的名称服务器会导致间歇性故障。


要更改 DNS 设置，请参阅 link:../administer/configure-kerberos-smb-single-node.html#fix-name-resolution["在单节点部署上为 SMB/CIFS 共享配置 Kerberos"] 或 link:../administer/configure-kerberos-smb-multi-node.html#fix-name-resolution["为多节点部署上的 SMB/CIFS 共享配置 Kerberos"] 中的“修复名称解析”。



[[host-packages]]
=== 主机包

[cols="1,3"]
|===
| 部署 | 所需软件包 


| 单节点 | Kerberos 客户端工具：Ubuntu 上的 `krb5-user` 或 RHEL 上的 `krb5-workstation`。安装程序会自动安装 `cifs-utils` 以支持 Kerberos 身份验证的 SMB 访问。 


| 多节点 | `cifs-utils` 在每个节点上，以及在您创建和测试 keytab 的主机上的 Kerberos 客户端工具和 NFS 客户端。 
|===
仅在基于 Kerberos 的 SMB/CIFS 扫描时，每个 AIDE 节点才需要  `cifs-utils`。单节点安装程序会安装它。在多节点部署中，您需要在每个节点上安装它。如果节点上缺少  `cifs-utils`，则对 SMB/CIFS 共享的 Kerberos 扫描将失败。



[[active-directory-attributes-for-nfs]]
=== NFS 的 Active Directory 属性

若要将 NFS 用户和组 ID 解析为 Active Directory 名称，必须填充 `uidNumber`和 `gidNumber`属性，并在 AIDE 查询时将其复制到全局目录。请参阅link:../administer/configure-ad-nfs.html["配置 NFS 的 Active Directory 身份映射"]。
